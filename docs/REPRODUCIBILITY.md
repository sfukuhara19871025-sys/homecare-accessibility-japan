# Reproducibility and study-scale metadata

## Computational scale recorded for the submission dataset

- 17,931 qualifying facilities.
- 466,792 source mesh–administrative-area records routed.
- 465,895 unique physical spatial centroids represented.
- 897 duplicated spatial keys caused by administrative population allocation.
- approximately 8.37 billion facility-record combinations processed by the national OSRM run.
- 61 source records/centroids were OSRM-unreachable in the primary routing output before the final unique-centroid collapse.

## Original workstation

- Dell 14 Plus DB14250
- Windows 11 Pro
- Intel Core Ultra 7 258V
- 32 GB RAM
- 1 TB SSD
- local consumer-grade execution; no HPC/cloud compute used for the national routing analysis.

## Reproducibility safeguards implemented in the public workflow

1. Input manifests/MD5 checks are generated by script 05.
2. The row-preserving crosswalk does not use `unique(mesh_id)` as a join strategy.
3. Duplicated spatial keys are checked for routing/distance invariance before national collapse.
4. Population totals are checked for conservation after unique-centroid aggregation.
5. OSRM-unreachable centroids remain in denominators and are treated as unreachable at all time thresholds.
6. Script 06 quantifies network snapping for both centroid destinations and facility origins, performs 500-m and 1-km sensitivity analyses, and reroutes the straight-line-nearest facility for same-facility comparison.

## Study mode vs reusable mode

Set `HOMECARE_STUDY_MODE=true` when reproducing the submission dataset. Script 05 then enforces the recorded source-record, unique-centroid, and duplicate-key counts. For synthetic or external datasets, leave study mode false.

## What cannot be reproduced from this repository alone

The original JMAP-derived facility-level dataset is third-party and is not redistributed. Exact numerical reproduction of the manuscript therefore requires the same source data (or an authorized equivalent copy) in addition to the public code and road-network snapshot.

## v1.0.0 validation

The v1.0.0 public workflow was runtime-tested on Windows with R 4.5.2. The bundled synthetic data completed scripts 01–06, including the updated script-06 v1.4.0 CSIS geocoding-QC block. Study-data scripts 05–06 were also rerun with `HOMECARE_STUDY_MODE=true`, reproducing the archived manuscript counts and technical-QC results. The new geocoding diagnostics did not alter the routing core or primary/same-facility estimands.

See `docs/VALIDATION.md` for details. Large study outputs and restricted JMAP-derived inputs are intentionally excluded from the repository.
